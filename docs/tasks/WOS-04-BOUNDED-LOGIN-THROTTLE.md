# Bounded login throttling

Addresses WOS-NFR-SEC-001/002/008 and WOS-NFR-MNT-005. The previous login map retained a key containing each distinct submitted username indefinitely, including attempts against disabled production local login. A shared identity module now uses fixed-size hashes, expiring fixed-window entries and a hard 10,000-entry bound. Reaching capacity rejects new keys until expiry without evicting live attempt budgets. Repeated denials do not grow counters. An aggregate IP budget also covers attempts that rotate usernames.

The default account/IP limit remains eight attempts per 15 minutes (LOGIN_RATE_LIMIT); LOGIN_IP_RATE_LIMIT defaults to 64 attempts per 15 minutes across usernames. Both must be positive safe integers. Entra callbacks continue through the same throttling controls. Local login disabled by production mode or LOCAL_LOGIN_ENABLED=false returns 404 before rate-limit state or database work. Existing trusted-proxy configuration remains authoritative for client IP extraction.

## Verification and operations

Five executable regression tests cover normalized account limits, expiry and Retry-After, rotating usernames and malformed input, large input with bounded retained keys, hard-cap denial without live eviction, cleanup, invalid configuration and actual HTTP disabled-login handling. Backend and authorization-convergence contracts pass. Type checking passes; syntax checking passes for 525 modules. Production build passes with existing bundle-size warnings. The signed production identity fixture passes against a freshly migrated disposable PostgreSQL database, including fail-closed startup and disabled/pending identity-link checks. The first fixture launch hit sandbox OpenSSL loading restrictions; the next exposed an uninitialized database. The successful run uses a dedicated migrated fixture database, not production data.

The full aggregate unit/contract suite passes (128 top-level commands). Its optional database date checks were subsequently executed against PostgreSQL: profile, terminology and working-calendar suites each pass in UTC, Asia/Kolkata and America/Los_Angeles (nine database/timezone runs).

No migration or dependency change. Dependencies reuse the verified parent lockfile installation. Exact-head hosted CI remains required. Rate-limit state is process-local and resets on process restart; multi-process deployments require an external shared limiter or ingress enforcement. Fixed windows and per-IP budgets can affect users behind a shared NAT; tune the documented IP limit for the buyer deployment while retaining ingress abuse controls. This bounded-memory repair is not a claim of comprehensive distributed denial-of-service protection. No deployment was performed. Rollback reintroduces unbounded retained input and should be avoided in favor of a forward correction.
