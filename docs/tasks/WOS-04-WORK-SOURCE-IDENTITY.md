## Concrete contract

- Add optional per-entry `sourceIdentity` (`source_identity` manual API): exact case-sensitive `{namespace, externalId}`. Namespace is an explicit producer/account namespace (ASCII token up to128 characters); externalId is explicit single-line Unicode up to200 characters. Reject leading/trailing whitespace, controls and malformed/partial objects; do not lowercase, normalize Unicode equivalence, infer a provider/worker/account or fetch/verify anything. Both fields blank means null only before first capture. Old omitted fields remain compatible.
- Identity is unique within authorized organization/legal entity plus namespace/ID, across workers, headers, states and retained captures. Different explicitly supplied namespaces/legal entities may use the same external ID. Conflict responses disclose no other worker/header/content. Scope/assignment/period validation precedes identity lookup.
- **Create-only explicit opt-in:** first successful capture retains one append-only claim tied to that stable header and canonical recorded work. Original identity/content cannot be changed, cleared, removed, rebound to another header/worker or silently replaced through these create/conflict commands. Changed-source corrections/amendments require the later versioned contract and are rejected here, rather than guessed. Ordinary untagged Draft/Rejected editing remains unchanged. This constraint is explicit when a new identity is supplied, not a default imposed on legacy work.
- Canonical content includes worker/header period, work date/type/project/client/category, exact decimal quantity, server-resolved billability, comment/evidence URL/reference. Persist a versioned allowlist, excluding regenerated local entry IDs, last writer, policy snapshots and future columns. Repeated unchanged Draft full-header saves retain the same claim without double-counting; unchanged same-key import replay returns its original result. No identity waives retained Submitted/Approved immutability or existing import natural-key/partial-result rules.
- Old clients preserve omitted identity independently of other metadata on a unique context match; ambiguity conflicts instead of erasing it. Source-aware full-header UI saves retain hidden/weekend/zero/context entries and exact keys across mode changes. Zero-hour source entries remain represented. Claims survive full entry-row replacement and guard direct SQL/concurrent writers under existing locks.
- Manual, both import aliases and optional CSV namespace/worklog-ID columns use the same normalization/claim/conflict rules. Preview validates existing claims plus staged accepted groups without business mutation; apply has the same deterministic group outcome. Existing batch/source row identifiers, partial results, idempotency and original Web/import provenance remain distinct from the self-asserted source key.
- New immutable submissions/audit/read/history projections retain source identity. Old work/history/claims are not fabricated or backfilled; namespace/ID never becomes actor or verified provenance. UI labels the exact create-only identity and retained source-linked work; recorded linked cells are read-only in ordinary entry editing. This does not create a task/milestone relationship, financial authority, external credential or provider integration.
- New clients require returned source-key acknowledgement before confirming a tagged manual save. New import batches retain a versioned source-check result/count/mode; old batches remain unchecked, and replay never fabricates current validation. Missing acknowledgement is an uncertain result requiring read-back, not a successful source capture.
- Migration053 adds only nullable entry identity and import-check metadata, strict shape checks, an append-only scoped claim ledger and additive registration/final-state guards. Existing work, policy, grants, decisions and financial history remain unchanged. No endpoint/grant to edit claims.
