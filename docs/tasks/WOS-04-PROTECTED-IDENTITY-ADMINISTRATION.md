# Protected identity administration

Addresses WOS-IAM-003/005/006/010 and WOS-NFR-SEC-003/004/005/008. Workforce editing must not implicitly grant security administration. Explicit role changes now require a current active Admin role and effective permissions.manage authority inside the transaction. New accounts default to Employee regardless of their code; omitted roles preserve existing assignments in both profile saves and imports. Removing the final assigned administrator from an affected active scope is rejected. Role changes append before/after audit evidence.

Login bindings and Entra group mappings require the same protected administrator authority in addition to integrations.identity. This applies to dedicated integration routes and profile/import binding changes. Omitted profile binding values are preserved. Existing Disabled or Pending links are authoritative over legacy subject columns: callbacks cannot reactivate them. Callback binding validation locks the employee record to serialize against binding administration. Legacy subjects may bootstrap a link only when no link exists.

Existing-account credentials can no longer be overwritten through initial_password on a profile save. The dedicated password-reset endpoint remains available to authorized workforce operators for ordinary Employee accounts; privileged roles or direct permission grants additionally require security-administrator authority. New profile/import passwords use the existing configurable password policy. Imports continue to preserve existing passwords.

## Verification and operations

Real disposable PostgreSQL/API negative tests cover role elevation, code prefixes, unchanged omitted roles, profile password replacement, privileged reset/binding, unauthorized role mapping, import elevation and omission, password policy with rollback, and last assigned administrator removal. Positive administrator role/mapping changes are included. The synthetic production Entra fixture verifies both Disabled and Pending link rejection and unchanged link state; its bounded test-only callback allowance increases from nine to eleven to include the two additional cases. Production defaults are unchanged.

Local type checking passed, syntax checking passed (517 modules), and production build passed (3069 modules; existing bundle-size and dependency annotation warnings remain). Focused PostgreSQL tests and the full production identity/startup fixture passed. The full aggregate unit/contract suite passed (127 top-level commands) after its callback-fixture assertion was updated for the two additional negative cases. Hosted CI remains required and is tracked in the Draft PR. Locked dependencies are unchanged and reuse the verified parent installation; no migration is added.

No deployment or production data mutation is performed. Rollback reopens privilege-assignment and identity-binding weaknesses; prefer a tested forward correction. The last-administrator check here covers role removal through these profile/import paths, not every account-disable or external identity lifecycle operation. This change does not implement per-session logout revocation, live tenant group-membership lookup, or a complete global permission-administration redesign. Identity-binding administration now requires Admin plus permissions.manage and integrations.identity; provisioning operators must use an authorized administrator for that action.
