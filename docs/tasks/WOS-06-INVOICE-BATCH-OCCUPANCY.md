# Invoice-ready draft membership and occupancy — bounded plan

## Requirement lineage and dependency

WOS-INV-001–003/005/006/008, CORE-003–005/008, IAM-003/005/010 and the commercial and approval specifications require versioned event → approved-unbilled item → invoice-ready membership lineage, scoped controls, database-unique current occupancy, retained audit and atomic pre-export cancellation. The integration uses migration 065g after the merged T&M billing register.

## Selected boundary and explicit choices

A currently authorized, in-scope finance preparer creates a `Draft` for an explicit legal entity, client, engagement, native currency, inclusive period and named current scoped batch owner. The preparer is the authenticated actor; no owner or preparer is inferred from a title or other project record. New preparation/read/cancellation capability definitions are opt-in only, with no role or user grants. An authorized buyer explicitly selects whether the period applies to the retained work date or the eligibility date; neither basis is preselected, and dates are never converted. For this first source-specific path, only current T&M approved-unbilled versions are available; no raw work entry or valuation snapshot is a line input.

A user explicitly inspects and selects an entire current item version. In one transaction, the server revalidates the existing event, work and approval chain, actor and owner scope, matching client/engagement/currency/selected date basis and batch state, then appends an immutable line and acquires a PostgreSQL-unique current-occupancy row keyed by the item ID/version. Same-key identical replay returns the retained line; changed key/input, duplicate same-batch or cross-batch item, partial/split input and concurrent competing acquisition conflict. The available register excludes occupied or stale items. Retained source IDs and native decimal values, line count and exact currency control totals remain inspectable without exposing cost/margin.

A separately authorized pre-export cancellation of a Draft requires explicit reason and audit. It atomically preserves all line/history evidence and releases that batch's current occupancy. Released items appear again only if their event and source remain current and in scope. A new Draft and new line/membership version may acquire them; previous rows are never rewritten. No `Under Review`, `Approved`, `Exported`, `Billed/Confirmed`, provider delivery or final artifact transition is made available by this bounded Draft-only slice; those canonical states remain reserved for their governed implementation. No statutory invoice, ledger posting, automatic scheduler, conversion, allocation, default terms or live external integration is added.
