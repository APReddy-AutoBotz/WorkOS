## Selected bounded workflow

An existing commercial administrator explicitly configures prospective billing or confidential-cost candidate approval policy with named existing account/held-role stages and explicit locale and canonical templates. No default approval policy, threshold, owner, approver or live grant is selected. Existing administrator and separate cost authority from the ownership phase remain independently necessary; cost decisions require cost visibility and employee relationship scope. If existing permissions cannot safely distinguish decision authority, define separate opt-in billing and cost approval decision permissions without role/user grants. Approvers must already hold the explicit role and required current scoped permissions; requester and affected worker may not decide their own change. Ownership remains separate from decision authority.

A request pins the exact candidate ID, latest candidate stream version, owner-event version and selected effective policy version. The server revalidates source scope, current owner account/role/read/inbox eligibility, requester and named stage relationships. Pending/intermediate/rejected requests produce no effective rate, valuation or invoice value. Any new candidate version, owner change, owner eligibility loss, policy/source mismatch or role/scope loss makes a stale request undecidable; an authorized fresh request must be reviewed. Historical owner, request, decision and recipient evidence remains immutable. Each current-stage command uses expected sequence/source/owner and exact request id; concurrency and replay serialize, changed requests conflict, uncertain outcomes require original read-only receipt reconciliation.

Persist canonical `approval.action_required` for the actual current stage; `approval.rejected_or_correction_required` resolves requester plus commercial owner and affected worker when applicable, server-side and deduplicated with all reasons. Validate the complete scoped recipient set and commit every required event, recipient and in-app delivery atomically with the transition. Optional `approval.completed` remains informational with existing preference/failure isolation. Never leak rate/cost amounts or entered private reasons through broad inbox, event payload or general audit. No client-selected recipients, external delivery, unattended scheduler, hidden default or source-identity transfer. Final approval is retained as candidate approval evidence only until a separately authorized authoritative adoption/valuation source contract exists; no approval decision alone creates invoice eligibility.
