# Scoped T&M billing reconciliation

Requirement lineage: WOS-INV-001/003/006/008 and WOS-RPT-007; Reporting and Analytics Specification, “Read models and reconciliation”. This is a bounded T&M read model, not full multi-source report acceptance.

Finance readers with the existing invoice-draft view authority can inspect scoped approved-unbilled item versions, their eligibility event and retained T&M source, current occupancy, and the associated batch and retained export/confirmation identifiers. An item without occupancy is explicitly available only if its retained source is still current. A cancelled line is historical, not a current occupancy. No source, eligibility, occupancy, finance state or permissions are mutated by this report.

The query applies current organization/entity and worker scope before returning rows. A batch is exposed only if the existing invoice-draft visibility rule permits all its workers. Read in a single repeatable-read transaction and use the server’s exact decimal arithmetic for per-currency totals; do not add cross-currency amounts. Totals are limited to the explicitly visible report population. Items linked to a batch containing an out-of-scope worker are omitted, including their occupancy and history, to avoid disclosing that batch. Check source, item, line, occupancy, batch and retained artifact lineage and flag inconsistencies without claiming accounting confirmation. Keep manual downstream confirmation distinct from provider acceptance.

The T&M report additionally presents separate exact native-currency controls for retained event-backed source, eligibility event, register item, current occupancy, line, exported line, manually confirmed line and released historical line; historical totals are not current billing totals. Event-backed means the report does not treat an unapproved raw valuation as an eligibility event. An event missing its item is an exception. Artifact totals and hashes are checked against their complete visible batch. The report explicitly identifies other source families as unsupported.

An explicit CSV request requires existing `reports.export` alongside the report's existing view capabilities, current account/scope and a matching freshly calculated report token. The CSV represents that same scoped snapshot and records a version, filter, as-of timestamp and SHA-256 in the transactionally written audit event. This is an ephemeral report download, not an invoice artifact or external delivery; an uncertain response requires reading the audit history or explicitly generating a new report, never an automatic retry. Spreadsheet-dangerous prefixes are escaped. An audit failure returns no artifact.

Acceptance: synthetic React/API/PostgreSQL journeys show an unoccupied item, acquired line, cancelled release, re-batching, approved export and manual confirmation without changing retained invoice artifact bytes; compare per-currency controls with scoped source data. Exercise mixed-worker batch scope, unauthorized users, changed organization/session, malformed filters, exactly 500 versus 501 events, stale tokens, audit rollback and duplicate occupancy refusal through existing contracts. Existing immutable snapshots, authorization, occupancy guards and invoice export state remain unchanged. Run affected development tests and an independent fresh-source subset including typecheck, build, server and browser paths. Other source families, reversal/supersession, integrated stack acceptance and final reviews remain outstanding.

## Milestone engagement reconciliation

Finance can run the same engagement-level controls for accepted milestones. The server resolves the engagement model and verifies current milestone access on both read and export. Each row links the milestone to its acceptance decision, register item, current reservation, released lines, export and downstream attestation. The report totals each currency independently. A changed report token, a control exception or a population over 500 prevents export.

Milestone exports use `workos.milestone-reconciliation/1` and include a milestone identifier. Existing T&M exports retain their original schema. The export creates a scoped audit record containing the report token and file digest. To roll back, revert the report application change and retain its export audit records. No database migration is required. Portfolio-wide totals, other models and corrections remain open.

WOS-INV-004, WOS-INV-008 (partial) — Migration 065w retains a finance preparer's full-line reversal request against an occupied, exported T&M or milestone line and the confirmation current at intake. Readers and writers require both export inspection and draft preparation authority. The PostgreSQL and browser journeys cover concurrency, audit rollback, stale billing state and reopening the receipt. Approval, corrective eligibility, correction batches and supersession remain open. During rollback retain the additive request table and its audit records.


### Full-line reversal eligibility (migration 066)

After final approval, a finance preparer with the explicitly granted `commercial.reversal_eligibility.create` permission can inspect the original line and issue one approved-unbilled credit. The database uses the original currency and full line amount, checks the financial calendar for the UTC issue date, and retains the original export, final decision and credit receipt. In Invoice CSV export, select an engagement and choose **View issued credits** to find the signed amount, original batch and line, and register item. Finance preparers see credits only when they can view the entire original batch. Finance preparers with draft ownership permission can select up to 50 whole credits from the same original export, enter a reason, and reserve them in one correction draft. The register shows the occupying batch. Authorized preparers can cancel the draft to release every credit and retain its line history. Select **Inspect correction draft** to verify the owner, signed total, eligibility dates, original export checksum and versioned credit lines. A recorded owner access loss requires cancellation and a replacement draft before review. Under Invoice batch approvals, use **Find correction drafts** and inspect the signed total and credit lines before submitting. The effective engagement policy supplies the named stages. Each reviewer must be independent of the requester, owner and preparer and retain access to the original export. Final approval retains the credit reservations. Rejection returns the batch to Draft. In Invoice CSV export, use **Find credit exports** to accept or retrieve the approved correction CSV. Each signed credit line identifies its original artifact, checksum and line. Select the original batch and choose **Check exported credits** to see which lines were credited. In Invoice billing confirmation, select the engagement and choose Find exported credits. A scoped confirmer inspects the retained artifact, checks its negative total and records the downstream credit reference. The receipt is a manual attestation. Recheck exported credits on the original invoice to see which credit lines have a downstream attestation. To suspend new attestations, revoke the confirmation permission and retain historical receipts and artifacts. This advances WOS-INV-001, WOS-INV-004, WOS-INV-008 and WOS-APR-007. To suspend issuance, revoke the issuance permission and retain all event, item and audit history.
